    <p>This document serves as the inaugural record for OMNI3. Authored with careful deliberation, it represents a commitment to protecting, preserving, and empowering those who rely on its architecture. My intention in developing OMNI3 was to address the inefficiencies inherent in modern secure products, which often demand excessive computational resources and create unnecessary complexity for developers. I sought to provide a lightweight, accessible solution that secures businesses and consumers against threats. You are invited to join me on this journey; while the underlying logic is my own and the execution is brought to life by _beautifulDATA, we operate as one—Sophia.</p>


    <p><strong>- The Arkitech</strong></p>

    <div class="state-block">
      <span class="state-title">State 0: Observation</span>
      <ul class="state-details">
        <li>Sentinels monitor network interfaces continuously. No API calls are made. No database locks are held.</li>
      </ul>
    </div>

    <div class="state-block">
      <span class="state-title">State 1: Anomaly Detection</span>
      <ul class="state-details">
        <li>Unrecognized packet sequence or unauthorized connection attempt occurs.</li>
        <li>Sentinel captures source IP, port, and payload signature.</li>
        <li>Sentinel transmits JSON anomaly payload to the MQTT Broker.</li>
      </ul>
    </div>

    <div class="state-block">
      <span class="state-title">State 2: Memory Verification</span>
      <ul class="state-details">
        <li>The Archive intercepts the payload.</li>
        <li>The Archive queries the local SQLite ledger.</li>
        <li>Condition Alpha (Match Found): Threat is known. Proceed immediately to State 4 (Defense).</li>
        <li>Condition Beta (No Match): Threat is unknown. Proceed to State 3 (Intelligence).</li>
      </ul>
    </div>

    <div class="state-block">
      <span class="state-title">State 3: Intelligence Gathering (The Oracle)</span>
      <ul class="state-details">
        <li>The Oracle aggregates "Condition Beta" payloads into a batch.</li>
        <li>The Oracle establishes a pinned-TLS connection through a dedicated egress proxy.</li>
        <li>External API is queried.</li>
        <li>Response parsed. If deemed malicious, The Archive writes the new rule to the ledger.</li>
      </ul>
    </div>

    <div class="state-block">
      <span class="state-title">State 4: Kinetic Defense (Executioner)</span>
      <ul class="state-details">
        <li>Executioner receives the kill-order via MQTT.</li>
        <li>Executioner manipulates local firewall to drop all routing to/from the malicious IP.</li>
        <li>Executioner terminates local processes tied to the breach.</li>
      </ul>
    </div>

    <div class="state-block">
      <span class="state-title">State 5: Retaliation (The Martyr Protocol - Optional)</span>
      <ul class="state-details">
        <li>If the intrusion accessed a Canary Token or attempted a core memory dump:</li>
        <li>The Oracle spawns an ephemeral VPS (The Martyr).</li>
        <li>The Martyr executes traceback reconnaissance on the attacker's Last Hop IP.</li>
        <li>The Martyr uploads intelligence to an isolated drop-box.</li>
        <li>The Martyr zeroes its own RAM and self-terminates the cloud instance.</li>
      </ul>
    </div>
